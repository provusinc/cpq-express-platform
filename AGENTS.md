# Conventions

Vocabulary comes from `CONTEXT.md` (the glossary) and decisions come from `docs/adr/`. Name code, tables, routes and UI copy with the glossary term, and avoid the words it lists under _Avoid_. For example, use Organization (not tenant or org) and Account (not customer). If code and the glossary disagree, that's a bug: fix one of them.

## Packages

Workspace packages are TypeScript source with no build step, imported as `@workspace/<name>`.

- `domain`: pure business rules (pricing, dates, status machine, permission policy). It has no I/O and no framework, and imports no other workspace package; lint enforces this. It is the only package shared by the browser and the server.
- `db`: Drizzle schema, `createDb`, the `db` singleton (`@workspace/db/client`, app only), migrations, the tenancy helpers (`organizationTable`, `organizationReference`, `organizationScope`), the Invitation token helpers (`createInvitationToken`, `hashInvitationToken`) and the seed (`@workspace/db/seed`). It also re-exports `drizzle-orm/sql` operators (`sql`, `eq`, …), so other packages import those from `@workspace/db`.
- `api`: tRPC routers and procedure tiers. It depends on `domain`, `db` and `auth`. `@workspace/api/headers` holds the request-header names and has no dependencies, so `proxy.ts` can import it.
- `auth`: Auth.js config and session helpers. `@workspace/auth` is framework-free (`getSessionFromHeaders`, `Session`, `resolveRedirect`) and safe in any server package; `@workspace/auth/next` is the Auth.js instance (`handlers`, `auth()`, `oauthProviders`), app only; `@workspace/auth/react` has client `signIn`/`signOut`; `@workspace/auth/env` is its env schema; `@workspace/auth/mailer` has the `Mailer` interface for every non-auth email, with `createSmtpMailer()` (the same SMTP settings as magic links) and `createMemoryMailer()` (an `outbox` array, for tests).
- `storage`: S3-compatible object storage (MinIO locally) for logos and Quote Documents; Postgres keeps only keys. `ObjectStorage` (`put`, `get`, `head`, `delete`, `presignPut(key, { contentType, size })` → `{ url, headers }` with type and length signed, `presignGet(key, { expiresIn?, downloadName? })`), `createS3Storage()` from the S3_* env (path-style for MinIO; `@workspace/storage/env` is its env schema) and `createMemoryStorage()` (an `objects` map, for tests). Keys are `organizationObjectKey(organizationId, area, name)` → `organizations/<id>/<area>/<name>`; check any key a client sends back with `isOrganizationObjectKey(key, organizationId, area)`. Browsers upload with a presigned PUT and read with a presigned GET, never through the app (MinIO's default CORS allows the browser PUT).
- `documents`: the Quote Document as `@react-pdf/renderer` components, shared by the browser preview and server rendering. `QuoteDocument({ snapshot, settings, logo })` (the `<Document>` tree; no hooks), the plain serialisable render input `QuoteDocumentSnapshot` / `QuoteDocumentInput` (Quote header and totals, Account + primary Contact for Bill To, company info, Phases, Line Items, Milestones, labels — never costs or margins; `logo` is a PNG/JPEG `data:` URL, SVG/WebP logos are not printed), `groupLinesByPhase`, and formatting from the Organization's currency and the document settings' locale/decimals (`formatDocumentMoney`, …; Helvetica only prints WinAnsi, so unprintable currency symbols fall back to the ISO code). `@workspace/documents/server` has `renderQuoteDocument(input) → Promise<Buffer>` (Node only). Its tsconfig is the react-library one (the api package's tsconfig has `jsx: react-jsx` so it can typecheck it). react-pdf quirk: an absolute View anchored with `bottom` isn't drawn — anchor with `top`.
- `apps/web`: calls the API only through tRPC: no Server Actions and no direct db access in components. The only route handlers are Auth.js, `/api/trpc`, Quote Document download (`app/api/documents/[id]/route.ts`: `openQuoteDocument` does the session + Membership check for the Host's Organization and returns the bytes; `?inline=1` opens in the browser) and `/api/health`.

Validate with the same domain rules as the API (e.g. `checkSlug`); the API re-validates, so map `fieldErrors(error)` back with `form.setError` and put anything else in `errors.root`. Admin-only pages check `membership.role` again on the server (see `members/page.tsx`, `settings/layout.tsx`); hiding the nav entry is not a check.
- **Label Overrides.** Never hard-code "Product", "Add-on", "Resource Role" or "Phase" in UI copy. Client components use `useLabels()` from `components/shell/labels.tsx` (`useLabels().resource_role.plural`, `useLabels()[kind].singular`); server components use `getLabels()` from `components/shell/get-labels.ts` (per request, canonical names on refusal, so it is safe in `generateMetadata`). Nav entries with a `term` are relabelled and hidden with it; a hidden term's page (Products, Add-ons) calls `notFound()`. Routes, code, API, CSV formats and the glossary keep the canonical terms. After saving labels, `router.refresh()` so the shell picks them up.
- **Quote editor** is `quotes/[quoteId]/`: `layout.tsx` checks the id (malformed, unknown or another Organization's → `notFound()`), prefetches `quote.byId` and renders `QuoteHeader` and `QuoteTabs` above the tab's route. Tabs are listed in `components/quotes/tabs.ts` (`QUOTE_TABS`: Line Items is the index route, then `planner`, `timeline`, `summary`, `financials`, `documents`); a ticket that builds a tab replaces its `QuoteTabPlaceholder` page. Read the open Quote with `useQuote(quoteId)` from `quote-header.tsx` (refetches on focus and every 30 s). Show or hide actions from `quote.permissions` (`canEdit`, `canDelete`, `canSubmit`, `canApprove`, …, and `editDenial` for the read-only notice); the approval actions are `ApprovalActions` (components/approval), passed to `QuoteHeader`'s `actions` slot by the layout; it also shows Mark as Sent and Customer approved / Customer rejected per `canMarkSent` / `canRecordCustomerOutcome` (one dialog per transition, its text going to the command's comment/notes/note). The header renders them before `QuoteHeaderActions` (`components/quotes/quote-actions.tsx`: Clone opens `CloneQuoteDialog`, the menu's Delete opens `DeleteQuoteDialog` when `canDelete`). Header fields autosave with `InlineText` (saves on blur/Enter, Escape reverts; `validate` refuses bad input with a toast) through `useQuoteCommand`.
- **Editor autosave (ADR-0003)** lives in `components/quotes/autosave.tsx`; every editor feature (#14 Phases, #15 Planner, #16 dates, #17 Timeline) uses it rather than its own mutations:
  - `useQuoteEditor(quoteId)` reads `quote.editor` (`{ quoteId, phases, lines, milestones, totals }`; every line carries its `allocations`), refetched on focus and every 30 s (`QUOTE_POLL_MS`). The tab page prefetches it (`prefetch(trpc.quote.editor.queryOptions({ id }))` + `<HydrateClient>`).
  - `useQuoteCommand(quoteId, trpc.<area>.<command>.mutationOptions(), { optimistic?, optimisticQuote?, onSuccess?, onError? })` returns a `useMutation`. `optimistic(editor, input) => editor` patches the cached editor (helpers: `patchLine`, `mergeEditorResult`); the totals are then re-priced in the browser with the domain `priceQuote` (`repriceLocally`), so the Summary moves at once. On success the command's `EditorResult` (`lines`, `deletedLineIds`, `phases`, `deletedPhaseIds`, `milestones`, `deletedMilestoneIds`, `totals`) is merged into `quote.editor` by `mergeEditorResult` and the totals into `quote.byId`; server values always win. On error both caches roll back and `toast.error(errorMessage(error))`. When the last in-flight command of the Quote settles, `quote.editor`, `quote.byId` and `quote.list` are invalidated. Extend `mergeEditorResult` when the result grows.
  - Every command's mutation key starts with `quoteCommandKey(quoteId)`; `<QuoteSaveIndicator quoteId />` (in the header) counts them for "Saving… / Saved" (`useQuoteSaveState`). There is no Save button.
  - Destructive commands return an `undoToken`; show `toast(…, { action: { label: "Undo", onClick: () => restore.mutate({ quoteId, undoToken }) } })` (see `components/line-items/commands.ts`).
  - Grid cells must keep a stable identity: TanStack's `FlexRender` renders `cell` functions as components, so define columns at module level and pass handlers through context (see `components/line-items/line-items-grid.tsx`), or an edit cell remounts and loses its draft on every re-render.
- **Tables (niko-table).** Every list and grid is built on niko-table (a shadcn registry of DataTable components on TanStack Table v9, vendored in `@workspace/ui/components/niko-table/*`; import each piece from its file, e.g. `…/niko-table/core/data-table-root`). Don't hand-roll `<Table>` lists; the plain shadcn `Table` stays only for static figure tables (Financials, Item type breakdown). Use the app kit `components/shell/data-table.tsx`:
  - **Server-side list** (anything `…list` pages): `ServerTableRoot` with `columns`, `data={list.data?.rows}`, `isLoading={list.isPending}`, `page`/`pageSize`/`total`/`onPageChange`, and only the state the API supports (`sorting`+`onSortingChange`, `columnFilters`+`onColumnFiltersChange`, `globalFilter`+`onGlobalFilterChange` for search, `rowSelection`, `columnVisibility`, `columnOrder`). It sets niko's `config` to manual paging/sorting/filtering, so the rows shown are exactly the page the API returned. The query input stays the source of truth: derive table state from it (`toColumnFilters({ columnId: values })`) and turn table changes back into input (`facetValues(filters, columnId)`), resetting to page 1 and clearing selection. Children: a `DataTableToolbarSection` with the kit's controls from `components/shell/table-toolbar.tsx` (`SearchFilter` with an `aria-label`, `FacetedFilter accessorKey=… options showCounts={false} limitToFilteredRows={false}` — static options, since only one page is loaded —, `DateRangeFilter accessorKey=…` whose value is `[fromMs, toMs]` of local midnights, `fromLocalDay`/`toLocalDay` in `lib/format.ts`, `ColumnsMenu`; not niko's own search/faceted/date/view components directly, see UI component policy), optional `DataTableSelectionBar`, `ListTable empty={…} filtered rowMenu={…}`, `ServerPagination total`. A filter with no visible column uses a filter-only column (`enableHiding: false`, hidden in `columnVisibility`); the faceted filter's `accessorKey` must equal the column id. The page awaits the first page with `prefetchNow` (not `prefetch`), or the server renders skeleton rows and the client real ones.
  - **Fully loaded list**: `LocalTableRoot` (`sortable` for client sorting) + `ListTable`.
  - **List pattern**: `PageHeader` (title, description, primary action) → `ViewTabs` (the status views with counts and the result count at the right, only where the tabs *replace* a filter: Accounts Active / Archived / All, catalog lists All / Active / Inactive via `activeViews` in `components/catalog/labels.ts`, Members by Role and Approvers, filtered locally) → toolbar → `ListTable` → pagination. The tabs replace a status faceted filter; never show both (the Quote list keeps its Status filter and has no tabs, its result count sits in the `PageHeader` description). A server list returns `statusCounts` (every view's count under all the *other* filters) next to `total`, computed in the same aggregate query. `ListTable`'s `empty` takes `action` (the primary action, e.g. New Quote, or New + Import CSV) and `filteredAction` (Clear filters). No dashboards on lists; the Dashboard is the one page of figures.
  - **Columns** are module-level `DataTableColumns<Row>` (`createDataTableColumnHelper<Row>()` for typed accessors), `meta.label` is the header text (`header: ColumnTitle`, or `SortableColumnTitle` for a sortable one; `meta.align: "end"` for numbers). Header functions must not call hooks: `DataTableRoot` calls them once while rendering to detect features, so a hook there breaks its hook order. Cells are components (TanStack's `flexRender` renders functions as components), so keep them module-level and pass handlers and settings through context. Names are one line; a Description is an optional column hidden by default (and the Name's `title`), never a subtitle.
  - **Select and row menu**: `selectColumn({ allLabel, rowLabel })` first, `actionsColumn({ label, Menu })` last. Write the row's actions once as a component using niko's `RowMenuItem`/`RowMenuSeparator`/`RowMenuSub…` and `useDataTableRow<Row>()`; the same component is the "…" dropdown (`actionsColumn`/`RowActionsMenu`) and the right-click menu (`ListTable rowMenu`, which wraps the table in the kit's `RowContextMenuArea`; a grid with its own body wraps its `DataTable` in `RowContextMenuArea` too). A menu label (`RowMenuLabel`, `DropdownMenuLabel`) must sit inside a `RowMenuGroup`/`DropdownMenuGroup` (Base UI throws otherwise). No column pinning on list pages.
  - The Quote list (`components/quotes/quotes-list.tsx`) also saves column show/hide/reorder per User in `user_preferences` via `user.preferences` / `user.setQuoteListColumns` (the kit's `ColumnsDndMenu` with the movable order, `resolveColumnLayout`/`toSavedLayout` from `lib/column-layout.ts`: unknown ids dropped, new columns slotted in, fixed columns always first — re-resolve after every menu change). It has no `ViewTabs` (they duplicated the Status filter); the result count, prefixed with the insight's name when arriving from the Dashboard, is in the `PageHeader` description. It takes `focus` / `initialFilters`: the page reads `?insight=<key>` or `?status=<status>` with `parseInsightFocus` and resolves it with `insightListFilters(focus, insightDays())` (`lib/key-insights.ts`; `insightDays` = this UTC month's first day and today) into the list input it prefetches; every Dashboard card is a `Link` to that URL (so a filtered list is shareable) and the list resets its filters when the focus changes. Filters without a toolbar control (`marginBelow`, the Valid Until range of `expiring_soon`) show as removable chips. The Key Insights are not on the list any more: they are on the Dashboard. Selection is per page and clears on any filter, sort or page change; the bulk bar's Delete calls `quote.deleteMany` and toasts the skipped Quotes with their reasons.
  - **Line Items grid** (`components/line-items/line-items-grid.tsx`) is a niko tree table: rows nested by Phase with `nestRows` (`lib/phase-tree.ts`) as `subRows`, collapse through the table's `expanded` state, only Line Items selectable (a module-level predicate passed as `config={{ enableRowSelection: selectableRows(canSelect) }}`). niko's row DnD reorders one flat sortable list, so the grid keeps dnd-kit with `resolveDrop` (into a Phase, before a line, the end zone, a whole selection) and renders its own body inside niko's `DataTable`/`DataTableHeader`, each row a drop target, with the right-click menus from `RowContextMenuArea`. The Resource Planner keeps its own `PlannerGrid`: niko's Data Grid owns rows in a local reducer and commits paste/fill as untracked bulk edits, which can't give one server-validated `allocation.setRange` per gesture.
  - `packages/ui` resolves imports like the bundler (the vendored code uses extensionless relative imports).
- **Settings** has one route per section under `settings/` (`company`, `quoting`, `labels`, `documents`), listed in `components/settings/tabs.ts` (label, one-line description, icon) and shown as a side nav (a row of links below `lg`); the Admin check is in `settings/layout.tsx`. Add a section with an entry there and its page.
- **Observing a page's query from above its `HydrateClient`** (the shell, the Quote editor layout): gate the component with `useHydrated()` and read with `enabled: false`. An observer created before the page's boundary hydrates makes it defer that query, so the page's `useSuspenseQuery` fetches it again during SSR without the session and the page 500s ("Sign in required"). The breadcrumbs and the editor ledger do this; the command menu mounts its queries only while open.
- **No `loading.tsx` above the Quote editor layout.** A Suspense boundary there streams the header in, and a click on Approve before it hydrates is lost. Only `quotes/[quoteId]/loading.tsx` (the tab body) exists.

## UI component policy (apps/web, packages/ui)

`packages/ui/src/components` and `packages/ui/src/hooks` hold only vendored code written by the shadcn CLI: every stock shadcn component (base-nova, Base UI) and the niko-table registry items. **Never edit these files.** Customise from outside instead, in this order:

1. **Call site**: `className` and props (Tailwind merges your classes over the stock ones; reach inner parts with data-slot selectors, e.g. `**:data-[slot=progress-indicator]:bg-success`).
2. **Wrapper or composition in `apps/web`**: a small component that renders the stock one with preset classes or props (`components/shell/empty.tsx`), or composes the library's lower-level exports (`components/shell/table-toolbar.tsx`, `RowContextMenuArea` and the column sort menu in `components/shell/data-table.tsx`).
3. **Theme tokens and base rules** in `packages/ui/src/styles/globals.css` (ours, not vendored). Its `@layer components` block holds the few global overrides of vendored markup, each with a comment saying why.
4. **Worst case**: copy the one file into `apps/web` under a different name and note it below with the reason. Clones today:
   - `apps/web/components/shell/columns-view-menu.tsx` (`ColumnsViewMenu`) and `columns-view-dnd-menu.tsx` (`ColumnsViewDndMenu`): niko's `filters/table-view-menu.tsx` / `table-view-dnd-menu.tsx` with the app's Columns popover design ("n of m shown" header, checkbox rows, padded Reset footer). The popover's inside can't be styled from outside. Port upstream fixes by hand.

Picking a component: use a stock shadcn component first, then one from a shadcn registry (`@niko-table` for tables), and write your own only when neither fits (domain composites like `QuoteStatusBadge` on `Badge`, the planner grid, the Gantt). Don't hand-roll what a stock component does: a spinning icon is `Spinner`, a segmented switch is `ToggleGroup`, choice cards are `RadioGroup` + `FieldLabel`, a bar is `Progress`, a linked list row is `Item`, `⌘K` is `Kbd`.

- **Adding and updating.** Everything is installed; run the CLI from `packages/ui` (`pnpm dlx shadcn@latest add <name> --overwrite`, or `@niko-table/<item>`, registered in both `components.json`). Check `--dry-run --diff` first: a re-add must report "skip (identical)" for every existing file. The CLI writes niko's registry `table.tsx` to `src/components/ui/table.tsx`; move it over `src/components/table.tsx`. **`table.tsx` is niko's `@niko-table/data-table-ui`** (shadcn's Table plus the `TableComponent` niko's `DataTable` imports and a keyboard-focusable scroll container), not shadcn's `table`: don't re-add shadcn `table` over it (`--all --overwrite` does, and typecheck then fails on `TableComponent`). Lint relaxes the React Compiler rules for the vendored folders only.
- **niko-table items installed**: `data-table` (+ `data-table-core`, `data-table-ui`), `data-table-pagination`, `-search-filter`, `-faceted-filter`, `-date-filter`, `-view-menu`, `-view-dnd-menu`, `-selection-bar`, `-column-sort`.
- **How the niko-table bugs are handled without editing it:**
  - Its popover triggers render a custom `trigger` inside their own `<button>` (the Base UI codemod dropped `asChild`), so a Button there nests buttons. `FacetedFilter` composes shadcn `Popover` with niko's `DataTableFacetedFilterContent`; `DateRangeFilter` (niko's) and `ColumnsMenu` / `ColumnsDndMenu` (our clones) pass a `TriggerFace` (a `<span>` styled as a Button) and globals.css makes the enclosing `<button>` a bare hit target.
  - Its row context menu wraps the `<tr>` in a `<div>`: use `RowContextMenuArea` (one shadcn `ContextMenu` around the table, resolving the row from `tr[data-row-id]`), never `DataTableRowContextMenu` or a body's `renderRowContextMenu`.
  - Its column sort menu puts a `DropdownMenuLabel` outside a group (Base UI throws): `SortableColumnTitle` renders the kit's sort menu around niko's `DataTableColumnSortOptions` in a `DropdownMenuGroup`.
  - Its search input hard-codes `aria-label="Search table"`: use the kit's `SearchFilter` (shadcn `InputGroup` on the table's global filter).
  - `DataTableRoot` overwrites a function `enableRowSelection` with its config boolean: pass the predicate through `config.enableRowSelection` with `selectableRows(fn)`.

## Design system (apps/web)

"Drafting ink": cool paper neutrals, petrol ink, iris as the second colour. Calm and dense for all-day use; boldness is spent on the figures.

- **Tokens** live in `packages/ui/src/styles/globals.css` for `:root` and `.dark`; use them, never raw palette classes (`amber-500`, `emerald-100`, …). `bg-canvas` is the backdrop the inset panel and auth screens sit on; `primary` is petrol, `iris` (+ `-soft`, `-ink`) the accent; `accent` is a petrol tint for hover/selected backgrounds (shadcn's meaning). Status tones come in three steps: `success|warning|danger|neutral` (solid: dots, bars, meters), `-soft` (badge fill), `-ink` (text on soft or on the surface). `series-1..3` are the chart colours (`SERIES`), also used by Gantt bars. Only floating things get `shadow-float`; the inset panel and the active nav item use `shadow-panel`; surfaces are otherwise separated by 1px borders. Radius base is 0.5rem.
- **Type**: IBM Plex Sans (variable) for everything, `.figure` (IBM Plex Sans Condensed, tabular lining numerals) for big numbers: Key Insight counts, Dashboard figures (open value, win rate), the editor ledger, totals, Financials stats. `td`, `th` and `dd` are tabular by default; add `tabular-nums` elsewhere money or quantities line up. Page titles are `text-2xl font-semibold tracking-[-0.015em]` (`PageHeader`); card titles stay `text-sm`/`text-base` medium. Sentence case everywhere; no all-caps labels.
- **Status colours**: `QuoteStatusBadge` (a dot and the glossary label) is the only way to show a Quote Status: Draft neutral, Pending Approval warning, Approved success-soft, Rejected and Customer Rejected danger, Pending Customer Approval iris ("with the customer"), Customer Approved solid success (final). `STATUS_SOLID` gives the matching solid colour for dots and the status-mix bar. Key Insight severity: warning/critical add a 3px top rule, a soft wash and a tag with the severity label. Catalog Active/Inactive use `ActiveBadge`. Low margin (below `LOW_MARGIN_THRESHOLD`) reads warning, negative danger.
- **Layout patterns**: the shell header is sticky (`h-13`) with breadcrumbs (only on nested pages — Quote, Account, Settings section — since a top-level page names itself in its title), the ⌘K trigger (which also starts a New Quote) and the theme toggle. New Quote as a button lives only on the Quote list. The Dashboard: `PageHeader` with the open value as a figure, the Key Insights strip (hairline grid, `gap-px` on `bg-border`), then a 12-column bento grid of `DashboardCard`s (8+4, 12, 4+4+4, 5+7; one column below `lg`), each with a link to the filtered list at its top right. Lists: `PageHeader`, `ViewTabs` where they replace a filter, toolbar, `ListTable` (its `LIST_TABLE_CLASS` header row is shared with the Line Items grid). ## Hosts and routing

One app serves every subdomain. `apps/web/proxy.ts` resolves the Host header (`lib/hosts.ts`, pure, never the DB) and rewrites to that surface's route tree under `app/hosts/`:

- `app.<ROOT_DOMAIN>/x` → `app/hosts/app/x` (sign-in, check-email, Invitation acceptance at `/invitations/[token]`, the Organization picker at `/`).
- `admin.<ROOT_DOMAIN>/x` → `app/hosts/admin/x` (Platform Admin console; its layout signs in and refuses non–Platform Admins).
- `{slug}.<ROOT_DOMAIN>/x` → `app/hosts/org/[slug]/x` (an Organization).
- Reserved subdomains (`app`, `admin`, `www`, `api`, `auth`, `docs`, `status`) are never Organizations; the reserved ones without a surface, nested subdomains and labels that can't be a slug get a 404, API included. Whether the Organization exists is decided by the server layer, never the proxy.
- `/api/*` is shared by every host and never rewritten. Direct requests to `/hosts/*` get a 404. Other hosts (bare root domain, `localhost`) pass through untouched.
- The proxy stamps every request (pages and `/api/*`) with `x-organization-slug` from the Host header, replacing any client-sent value, and with `x-request-path` (the public path + query). So the tRPC route handler and the RSC caller (`getCaller()`) both know the request's Organization without the client sending anything.

Links and `redirect()` inside a surface use the public path (`/sign-in`), not `/hosts/app/sign-in`.

## Authentication

- Auth.js v5 with the Drizzle adapter and database sessions. The providers are email magic link over SMTP (Mailpit locally, at http://localhost:8025), plus Google and Microsoft Entra ID, each only when its `AUTH_*` credentials are set. There is no credentials provider.
- The session cookie (`authjs.session-token`, or `__Secure-…` on https) is scoped to `.<ROOT_DOMAIN>`, so every subdomain sees it. Sign-in and sign-out happen on `app.`, and sign-out deletes the DB session. Auth.js builds its URLs from `APP_URL`, and redirects are allowed only to `<ROOT_DOMAIN>` and its subdomains (`resolveRedirect`).
- To send someone to sign in from another subdomain, redirect them to `signInUrl(<absolute url>)` from `@/lib/urls`, i.e. `${APP_URL}/sign-in?callbackUrl=…`. The Organization layout does this with the current URL.
- Server code reads the session via tRPC: `ctx.session` in procedures, or `(await getCaller()).auth.getSession()` in server components. Client components call `signIn`/`signOut` from `@workspace/auth/react`, never Server Actions.
- The global identity tables (`users`, `auth_accounts`, `sessions`, `verification_tokens`) are in `packages/db/src/schema/auth.ts` and have no `organization_id`. `users.is_platform_admin` marks a Platform Admin. Auth.js's OAuth accounts table is `auth_accounts` (`schema.authAccounts`), because `accounts` is the business Account.

## Tenancy (ADR-0001)

- `organizations` (slug, name, `currency_code`) is the tenancy root. Slugs are DNS labels, unique, never reserved (check constraints) and immutable (a trigger rejects changes). `memberships` holds `(organization_id, user_id)` unique, `role` (`admin` | `manager` | `member`, pg enum `membership_role`) and `is_approver`. Platform Admin is `users.is_platform_admin`, and it grants no Organization access: support staff need a normal Membership.
- **Every business table** is declared with `organizationTable(name, columns, extra?)` from `@workspace/db` instead of `pgTable`. It adds `id` (UUIDv7), `organization_id` (→ organizations) and the unique `(organization_id, id)` key.
- **Every reference between business tables** is a composite FK via `organizationReference(t, t.xId, xTable)` in the extra config: `(organization_id, x_id) → x(organization_id, id)`. Keep `xId: uuid()` without `.references()`. Chain `.onDelete(...)` as needed, but never `set null` (it would null `organization_id`); nullable references just work. References to global tables (users) stay plain `.references()`. The full recipe and an example are in `packages/db/src/organization-table.ts`.
- `phases` (quote, nullable `parent_id`, name, `sequence` among siblings; the parent must be in the same Quote via `(organization_id, quote_id, parent_id) → phases(organization_id, quote_id, id)`, cascading to descendants and their Line Items). `line_items`: quote (cascade), `phase_id` (nullable, same-Quote composite FK, cascade), `source_kind` (pg enum), `catalog_item_id` / `resource_role_id` (RESTRICT; a check requires exactly the one matching the kind, Resource Role ⇒ hour, Product ⇒ each), name, description, notes, start/end date (end ≥ start), `billing_unit`, `base_price`/`base_cost` (the Base Rate), `unit_price`/`unit_cost`, `quantity` numeric(18,3), `line_total`, `line_margin_pct` (computed), `sequence` (order within its Phase, or among Phase-less lines). `allocations` (line item cascade, `period_type`, `period_start`, `amount` > 0, unique per (line, period type, period start)), written by the Resource Planner; a line with Allocations is planner-managed. Lines get Allocations when the Planner first touches them (seeded from `defaultAllocations`, which is also what the Planner shows for an untouched line). `undo_snapshots` holds short-lived undo payloads. `milestones` (quote cascade, name, `date`, `type` pg enum `milestone_type` from `MILESTONE_TYPES`, `colour` checked `#rrggbb`, `completed`, description) carries no price.
- `quotes` (a business table): `owner_id` is the Quote Owner (the creating User, never transferred; a plain FK to global `users`, so a removed member stays owner), `created_by_id`/`updated_by_id`, `account_id` (composite FK, ON DELETE RESTRICT), Name (required, not unique), Description, `start_date`/`end_date` (`date`, read as ISO strings; check end ≥ start), `valid_until`, `time_period` and `status` (pg enums), `currency_code` (the Organization's, snapshotted), `discount_kind`/`discount_value` (both null or both set) and the persisted totals `subtotal`, `discount_amount`, `total`, `cost`, `margin` (numeric(19,4)) and `margin_pct` (numeric(7,4)). `user_preferences` is global (one row per User, typed columns) for UI preferences. `approval_steps` (quote cascade, `action` pg enum `approval_step_action` from `APPROVAL_STEP_ACTIONS`, `from_status`/`to_status`, `actor_id` → users, optional `comment`, `created_at`; append-only) is the approval history. `cost_change_log` (quote and line item cascade, `source_kind`, `source_id` (no FK) and `source_name` snapshot, `old_cost`/`new_cost`, `actor_id`, `created_at`) is written by Cost Propagation.
- **Access business rows only through the Organization scope.** In procedures that is `ctx.scope` (an `OrganizationScope`): `findById`, `findMany({ where, orderBy, limit })`, `insert`, `insertMany`, `update(table, id, changes)`, `delete(table, id)` and `transaction(fn)`. Every call is filtered by (or stamped with) the Organization, and `update` ignores `organizationId`/`id`. For joins, use `ctx.scope.db` and put `ctx.scope.where(table, …conditions)` on every business table in the query (see `routers/membership.ts`). A missing row comes back `undefined`; turn it into `NOT_FOUND`.
- Enum literals (`ROLES`, …) and the slug rules (`RESERVED_SLUGS`, `SLUG_PATTERN`, `checkSlug`) live only in `@workspace/domain`. The db builds its pg enum and check constraints from them, the API validates with them, and `lib/hosts.ts` resolves subdomains with `checkSlug`, so they can't drift.

## Invitations

- An Invitation (`invitations`, a business table) has an email (stored lowercase), a Role, a SHA-256 `token_hash` (the raw token only ever appears in the emailed link `APP_URL/invitations/<token>`), `expires_at` (7 days, `INVITATION_TTL_MS`), `accepted_at`/`accepted_by_id`, `revoked_at` and `invited_by_id`. It is *open* until accepted or revoked, and an Organization has at most one open Invitation per email (partial unique index).
- Issue and re-send only through `issueInvitation` / `reissueInvitation` in `packages/api/src/invitations.ts`, inside the command's transaction. They revoke an earlier open Invitation for the same email, refuse an existing member (CONFLICT), and send the email last, so a failed send keeps nothing. `invitationStatus(inv)` gives `pending | expired | accepted | revoked`.
- `invitation.byToken` is public (holding the token is the credential) and backs the accept page, which explains unusable links without sign-in. `invitation.accept` is authed and requires the signed-in User's email to equal the invited one (FORBIDDEN otherwise, so a forwarded link can't be used by someone else); expired, revoked or used → PRECONDITION_FAILED. It creates the Membership with the invited Role (an existing Membership is kept as it is) and returns the Organization, and the page then goes to its subdomain.
- Admins invite from the Members page (`invitation.create` with any Role). `resend` issues a new token (the old link stops working) and a fresh 7-day expiry, also for an expired Invitation; `revoke` is idempotent and refuses an accepted one.

## Money (ADR-0002)

- Store money as `numeric(19,4)`, percentages as `numeric(7,4)` and quantities as `numeric(18,3)`. Postgres returns these as strings; wrap them with `Decimal` from `@workspace/domain`.
- Do all arithmetic with `Decimal`, never JS `number`. Keep values as strings at the API boundary.
- The server recomputes totals through the domain pricing engine and ignores totals sent by the client.

## Domain package API

Import from `@workspace/domain/<area>`; the root `@workspace/domain` re-exports every area. All functions are pure and take and return plain serialisable data.

- **Boundary types.** Decimal inputs accept `string | number | Decimal`, so pass Postgres `numeric` strings straight in. Decimal outputs are strings at their column's storage scale: money has 4 dp (`"1234.5000"`), percentages 4 dp, and quantities and Allocation amounts 3 dp. Compare them with `Decimal`.
- **Refusals.** Business refusals come back as values (`{ allowed: false, reason, message }` or `{ ok: false, reason, message }`), never as thrown errors. Map `reason` to a tRPC error code and show `message`.
- `enums`: `ROLES`, `QUOTE_STATUSES`, `APPROVAL_STEP_ACTIONS`, `TIME_PERIODS`, `PERIOD_TYPES`, `BILLING_UNITS`, `SOURCE_KINDS`, `CATALOG_ITEM_KINDS`, `DISCOUNT_KINDS` and `MILESTONE_TYPES`, as const arrays with matching union types. db enums and zod schemas are built from these arrays.
- `money`: `Decimal`, `currencyMinorUnit`, `roundToMinorUnit` (half-up), `sumDecimals`, and `toMoneyString`, `toPercentString` and `toQuantityString` for storage-scale strings.
- `pricing`: `priceQuote({ currency, lines, discount })` returns per-line totals and margins, Subtotal, discountAmount, Total, cost, Margin and marginPct. Call it after every command and persist the result. It also has `hoursPerTimePeriod` and `defaultLineItemQuantity`, which use the Organization's Hours Per Day.
- `status`: `nextStatus(status, action)`, `availableActions`, `isLocked`, `isTerminal`, `LOCKED_STATUSES`, and `canSubmit({ status, total })`, which gives the specific refusal reason.
- `policy`: `can(actor, action, quote?, settings?)` answers every permission question, for Quote actions and for Admin-only Organization actions. `checkDeletableStatuses` validates the deletable-status setting, and `DELETABLE_STATUS_OPTIONS` lists the statuses that may be in it.
- `dates`: dates are ISO `yyyy-MM-dd` strings (`IsoDate`) and never `Date`. Validate input with `isIsoDate`. The module also covers bucket maths (`periodTypeForTimePeriod`, `startOfPeriod`, `endOfPeriod`, `addPeriods`, `periodsBetween`, `periodStartsInRange`), `countWorkingDays` (Mon–Fri) and day arithmetic.
- `effort`: `distributeWholeUnits(total, weights)` splits a total into whole hours by largest remainder, and the parts always add up to the total exactly.
- `allocations`: planner rules. `checkAllocationAmount` checks the per-cell caps and requires whole numbers for Each. `applyAllocationEdits` applies one gesture's batch of cells atomically. `defaultAllocations` lays out a new Resource Role line; call it when the line is added. `resizeAllocatedEffort` changes the total Effort. `diffAllocations` returns the rows to upsert and delete. Each of these returns the Allocations together with the quantity (Σ Allocations) and the dates they imply, so persist all of them together.
- `schedule`: `changeQuoteDates` handles a Quote Shift (the default for a start move) or a clamp, and returns every line's new schedule plus an impact summary. `changeQuoteWindow` moves both dates in one gesture (start, then end) with one combined impact summary; the Quote date editor uses it. Preview mode means the API does not persist that result. `changeLineItemStart` moves one line by lift-and-shift and trims at the Quote End Date.
- `phases`: `canPlacePhase` checks create and move, `validatePhaseTree` checks a whole tree (depth ≤ 3, no cycles), and `phaseSubtree` returns what a Phase delete removes. Grid order is `phaseTreeOrder(phases, lines)` (in every container its Line Items first, by `sequence`, then its child Phases, by `sequence`, depth-first); `placeBefore(ordered, moving, beforeId)` is the reorder rule every move uses (API and optimistic client alike); `phaseRollups(phases, lines)` derives each Phase's descendant counts, total, cost, margin and date span (never stored; also the delete confirmation's counts).
- `milestones`: `checkMilestoneColour` (`#rgb`/`#rrggbb` → lowercase `#rrggbb`), `DEFAULT_MILESTONE_COLOURS` per type, `MILESTONE_NAME_MAX`, `MILESTONE_DESCRIPTION_MAX`. `enums` has `MILESTONE_TYPE_LABELS`.
- `organizations`: `RESERVED_SLUGS`, `SLUG_PATTERN`, `checkSlug(slug)` (format and reserved; uniqueness is the API's), `suggestSlug(name)`, `isCurrencyCode` and `supportedCurrencies()`. `enums` also has `ROLE_LABELS` for UI copy and emails.
- `quotes`: `suggestQuoteName(accountName, startDate)` → "Initech – Oct 2026" (the create dialog's prefill), `sameQuoteName`, `QUOTE_NAME_MAX`. `policy` also has `quotePermissions(actor, facts, settings)`, every Quote action's decision at once (what `quote.byId` returns as `permissions`; `editDenial` and `submitDenial` carry the reason and message). `enums` has `TIME_PERIOD_LABELS`.
- `settings`: `checkHoursPerDay(input)` (> 0, ≤ 24, 2 dp; normalises to `"7.50"`), `DEFAULT_HOURS_PER_DAY_VALUE`; Label Overrides: `DEFAULT_LABELS`, `HIDEABLE_LABEL_TERMS` (Products and Add-ons only; Resource Roles and Phases can only be renamed), `checkLabelOverride` (trims; blank or canonical → `null`), `resolveLabels(overrides)` → `Labels` (`{ [term]: { singular, plural, enabled } }`); logo: `checkLogoFile({ contentType, size })` (PNG/JPEG/SVG/WebP, ≤ `LOGO_MAX_BYTES` 2 MB). `enums` has `LABEL_TERMS` and `QUOTE_STATUS_LABELS`.
- `documents`: document settings rules — `DOCUMENT_FORMATS`, `DOCUMENT_SECTIONS` (+ labels), `DEFAULT_DOCUMENT_SETTINGS`, `checkDocumentSettings` (normalises colours to `#rrggbb`, completes the section list, canonical locale), `sectionsToColumns`/`sectionsFromColumns`; and `canDeleteQuoteDocument(actor, quote, document)` (Owner or Admin → else `owner_or_admin_only`/FORBIDDEN; captured by Mark as Sent → `document_captured`/PRECONDITION_FAILED).
- `financials`: `buildFinancials({ currency, granularity: "month" | "quarter" | "year", quote: { startDate, endDate }, lines, discountAmount, allocationPeriodType?, hoursPerDay })` → buckets (`grossRevenue`, `discount`, `revenue` = cash inflow, `cost`, `margin`, `hours`, `headcount` FTE) and totals. Revenue, cost and Resource Role hours are prorated by calendar-day overlap (a planner-managed line by its Allocations' periods); the Quote Discount is spread in proportion to bucket revenue; sums are exact (largest remainder in minor units), so buckets add up to Subtotal / discount / Total / cost. `breakdownByItemType(lines)` gives revenue, cost, own margin and share of the Subtotal per labour / Products / Add-ons.
- `insights`: the Key Insight definitions — `INSIGHT_KEYS` (display order) and `INSIGHT_LABELS`, the status sets `PENDING_APPROVAL_STATUSES`, `PIPELINE_STATUSES`, `REJECTED_STATUSES`, `DECIDED_STATUSES`, `LOW_MARGIN_STATUSES` (the rest) and `EXPIRING_STATUSES` (offers in play: Draft, Pending Approval, Approved, Pending Customer Approval), `LOW_MARGIN_THRESHOLD` (`"15"`), `isLowMargin`, `EXPIRING_SOON_DAYS` (14), `expiringWindow(today)` (today … +14, inclusive), `isExpiringSoon`, `daysUntil(date, today)`, `insightSeverity(key, { count, oldestAgeDays })` (pending: critical ≥ 5 or ≥ 7 days, warning ≥ 2 or ≥ 3 days; low margin and expiring soon: warning when any; rejected: warning ≥ 3; else info), `ageInDays(since, now)`, `utcDay(now)` and `startOfUtcMonth(now)` (days and months are UTC; Organizations have no timezone).
- `dashboard`: `OPEN_STATUSES` (no customer outcome yet; Top Accounts rank by these), `WON_STATUS` / `LOST_STATUS`, `winRate(won, lost)` (percent string, `null` before the first outcome), `recentUtcMonths(now, n)` (month starts, oldest first), `fillMonths(months, rows)` (zero-filled monthly activity), `DASHBOARD_MONTHS` (12), `DASHBOARD_LIST_LIMIT` (5).
- `members`: `checkMembershipChange(target, change, adminCount)`, the last-Admin guard (the last Admin can't be removed or given another Role, not even by themselves). The API applies it under a row lock on the Organization's Admin Memberships; the Members page uses it to disable controls.

## tRPC

- Add a router in `packages/api/src/routers/<area>.ts` and register it under its area name in `src/root.ts`.
- Build each procedure on the narrowest tier in `src/trpc.ts`, which documents the tiers:
  - `publicProcedure`: anyone.
  - `authedProcedure`: gives non-null `ctx.session` and `ctx.user`, and throws UNAUTHORIZED otherwise.
  - `organizationProcedure`: authed, plus a Membership in the request's Organization (from `x-organization-slug`). It adds `ctx.organization` (`id`, `slug`, `name`, `currencyCode`), `ctx.membership` (`id`, `role`, `isApprover`) and `ctx.scope`. All business data goes through this tier's `ctx.scope`.
  - `adminProcedure`: organization tier with Role = Admin.
  - `platformProcedure`: authed Platform Admin, with no Organization.
  - `permittedProcedure(action)`: organization tier where `can(ctx.actor, action)` allows an Organization action (`"members.manage"`, `"settings.manage"`, `"catalog.manage"`); FORBIDDEN with the policy's message otherwise. The organization tier also gives `ctx.actor` (`userId`, `role`, `isApprover`), the policy's `Actor`.
- The context also carries `ctx.mailer` (a `Mailer`; SMTP by default), `ctx.appUrl` (APP_URL, for links in emails) and `ctx.storage` (an `ObjectStorage`; S3 by default). `createTRPCContext` takes all three as options, which is how tests capture email and objects.
- Refusals are uniform, so they never reveal what exists: no session → UNAUTHORIZED; no slug header (e.g. called from `app.`) → BAD_REQUEST; an unknown Organization **or** no Membership → NOT_FOUND (identical); another Organization's record id → NOT_FOUND; a Member without the needed Role or Approver right, or a non–Platform Admin → FORBIDDEN.
- `organization.current` returns the request's Organization and Membership. `organization.listMine` (authed) lists the caller's Memberships for the picker and switcher. `membership.list` and `membership.byId` are the first scoped reads. `platform.listOrganizations` / `createOrganization` / `inviteAdmin` are the Platform Admin console. The Members page uses `membership.list` plus the `members.manage` commands `invitation.list` / `create` / `resend` / `revoke` and `membership.changeRole` / `setApprover` / `remove` (removal deletes only the Membership; the User and everything they own stay).
- **Organization settings.** Company information and `logo_key` are columns of `organizations` (the company name is the Organization's `name`); Hours Per Day and deletable statuses are `organization_settings` (1:1, created on the first save); Label Overrides are `label_overrides` (one row per term). Document settings are `document_settings` (1:1, typed columns: `format` enum, `primary_color`/`accent_color` hex checks, `section_order` + `hidden_sections` as `document_section[]`, `money_decimals` (null = currency's), `quantity_decimals`, `locale`, `footer_text`, `terms`); read with `getDocumentSettings(scope)` (→ the domain's `DocumentSettings`, sections as `{ section, visible }[]` in order), set with `settings.updateDocuments` (validated by the domain's `checkDocumentSettings`), read by any member with `settings.documents`. Read them in any command with `getOrganizationSettings(scope)` → `{ hoursPerDay: "8.00", deletableStatuses }` (pass `hoursPerDay` to the pricing functions and `{ deletableStatuses }` to `can(…, "quote.delete", …)`), `getLabels(scope)` and `getCompany(scope, storage)` (with a 1-hour presigned `logoUrl`), all from `packages/api/src/settings.ts`; they return defaults until saved. Procedures: `settings.labels` / `quoting` / `company` for every member; `settings.manage` commands `updateCompany`, `updateQuoting`, `updateLabels`, and the logo upload `requestLogoUpload({ contentType, size })` → presigned PUT, browser PUTs, `confirmLogoUpload({ key })` (re-checks the object, NOT_FOUND for a key outside this Organization's `logo/` area, deletes the previous object) and `removeLogo`. The `quote_status` pg enum lives in `schema/enums.ts` for the Quotes table to reuse.
- **Quote commands** go through `quoteCommand(ctx, quoteId, action, fn)` from `src/quotes.ts`: it opens a transaction, loads the Quote through the scope with `FOR UPDATE` (commands on one Quote serialize), builds the policy facts (`ownerRole` = the owner's current Membership Role, `null` once removed; deletable statuses for `quote.delete`) and checks `can(actor, action, facts, settings)`. Missing or another Organization's → NOT_FOUND; a refusal about who is asking → FORBIDDEN; about the Quote's state (`locked`, `wrong_status`, `status_not_deletable`, Total not positive) → PRECONDITION_FAILED, with the policy's message (`denialError`). `fn` gets `{ scope, quote, facts, actor, update, reprice }`; `update(changes)` writes only those fields plus `updated_by_id` (last write wins per field) and returns the row; `reprice()` runs `recomputeQuoteTotals`. Header commands return only the changed fields (plus `updatedAt`, `updatedById`); editor commands return the standard `EditorResult` (below). `loadQuoteForCommand(scope, actor, id, action)` is the same check for use inside an existing transaction, and `quoteFacts(scope, quote)` builds facts for reads.
- Quote procedures: `quote.list` (server-paged; `search` over Name, Description and Account name; `statuses[]`, `accountId`, `createdFrom`/`createdTo` as UTC days, `owner: "all" | "mine"`, `marginBelow` (Margin % below it with a positive Total, the low-margin rule), `sort: { by, direction }` over `QUOTE_SORT_COLUMNS`; rows carry `validUntilPassed`, before today in UTC), `quote.filterOptions` (Accounts that have Quotes), `quote.nameTaken({ accountId, name, exceptId? })` (the non-blocking duplicate-Name warning), `quote.create` (any member; unarchived Account, end ≥ start; returns `{ id, name }`), `quote.byId` (header, Account, Owner with `isMember`, `updatedBy`, `locked`, `permissions`), the header commands `quote.rename` and `quote.setDescription`, `quote.editor({ id })` (Phases, Line Items in order, totals; any member) `quote.setDiscount({ id, discount: { kind: "percent", value } | { kind: "amount", value } | null })` (percent 0–100, 4 dp; the entered kind stays authoritative, the amount is capped at the Subtotal so Total ≥ 0), and the schedule commands in `routers/quote-schedule.ts` (spread into the quote router): `quote.setDates({ id, startDate, endDate, mode: "shift" | "clamp" = "shift", preview = false })` runs the domain's `changeQuoteWindow` (start move first — Quote Shift or clamp — then the end; outward changes nothing else; refusals BAD_REQUEST) and returns `{ preview: true, startDate, endDate, impact }` without writing, or applies it in one command and returns `EditorResult` + `startDate`, `endDate`, `impact` (`impactedCount`, `clampedCount`, `effortReducedCount`, `lines`, `oldTotal` → `newTotal` priced from the resulting lines); `quote.setTimePeriod({ id, timePeriod })` discards every Allocation on the Quote (quantities kept) and returns `EditorResult` + `timePeriod`, `discardedAllocations`. Changing dates or Time Period makes earlier undo tokens unrestorable. In the web app the header's `QuoteDatesEditor` (dialog, live preview via a plain `useMutation`, apply via `useQuoteCommand`) and `TimePeriodControl` (AlertDialog warning) live in `components/quotes/quote-schedule.tsx`. - **Clone and delete** (`routers/quote-clone.ts`, `routers/quote-delete.ts`, spread into the quote router): `quote.clone({ id, accountId?, refreshRates = false })` → `{ id, name }`: any member, any status (cloning changes nothing on the source); a new Draft "Copy of {name}" owned and created by the caller, on `accountId` or the source's Account (NOT_FOUND if not ours, PRECONDITION_FAILED if archived), with the source's header fields (Description, dates, Valid Until, Time Period, currency) and Quote Discount, the Phase tree (parents remapped), every Line Item with its Allocations (`copyLines` with a `quoteId` in the placement) and the Milestones with `completed` reset, repriced with `recomputeQuoteTotals`. `refreshRates` re-snapshots each line's Base Rate from its active source's current price/cost; unit price/cost follow unless they had been overridden (differ from the old Base Rate), and inactive sources keep the snapshot. Clone reads only those tables, so Approval Steps, Quote Documents, cost log entries and undo snapshots are never copied — a new Quote-owned table isn't cloned unless added there on purpose. `quote.delete({ id })` → `{ id, name }` runs `quoteCommand(…, "quote.delete", …)` (Owner or Admin, deletable statuses) and hard-deletes the row; the FKs cascade to every child. Storage objects are collected inside the command by `quoteDocumentKeys(scope, quoteId)` and removed after it commits (a failed removal is logged, not reported). `quote.deleteMany({ ids })` (≤ 100; NOT_FOUND if any id isn't this Organization's) applies the same command per Quote, each in its own transaction, and returns `{ deleted: { id, name }[], skipped: { id, name, reason }[] }` (reason = the refusal's message).
- **Approval** (`src/approval.ts`, procedures in `routers/quote-approval.ts`, spread into the `quote` router): `quote.submit` / `approve` / `reject` / `recall({ id, comment? })` are `quoteCommand`s on the matching policy action (Owner-only submit with the per-reason messages; Approver-only approve/reject, never on their own Quote; Owner-or-Admin recall), whose body is `transitionQuote(cmd, stepAction, comment)`: it sets `nextStatus(...)` and appends the Approval Step, returning `{ id, status, updatedAt, updatedById, step }`. `quote.markSent({ id, notes? })` (Owner or Admin, Approved → Pending Customer Approval) runs `transitionQuote(cmd, "mark_sent", notes)` then `generateQuoteDocument(cmd.scope, …, { capturedByMarkSent: true })` in the same `quoteCommand`, so a render/storage failure changes nothing; if the transaction fails after the upload it removes the object (`storageKey` in `generateQuoteDocument`'s result, never returned to clients). `notes` are both the Document's notes and the step's comment; it returns the transition plus the captured `document`. `quote.recordCustomerOutcome({ id, outcome: "approved" | "rejected", note? })` (Owner or Admin, from Pending Customer Approval) writes a `customer_approved` / `customer_rejected` step: Customer Approved is terminal and locked, Customer Rejected unlocks and can be submitted again. Valid Until never changes status (nothing reads it but the list's `validUntilPassed`). The seed gives its Pending Customer Approval / Customer Approved Quotes no captured Document (the seed lives in `db`, which can't import the api's generator or need MinIO). `quote.approvalHistory({ id })` (any member; steps oldest first with `actor`) and `quote.awaitingMyApproval({ page, pageSize })` (Approvers only, else FORBIDDEN; other people's Pending Approval Quotes, longest-waiting first, with `submittedAt` / `submitComment` from the latest submit step). Editing commands are refused while locked by `quote.edit`'s lock rule.
- **Pricing (ADR-0002).** `recomputeQuoteTotals(scope, quoteId, { updatedById })` from `@workspace/db` (it lives in `db` so the seed uses it too) is the only writer of money columns: it loads the Quote's Line Items in grid order and its Quote Discount, runs the domain `priceQuote` in the Quote's currency, writes `line_total`/`line_margin_pct` on changed lines and the Quote's `subtotal`, `discount_amount`, `total`, `cost`, `margin`, `margin_pct` (+ `updated_by_id`), and returns `{ totals: QuoteTotalsRow, lines }`. Inside `quoteCommand` call `cmd.reprice()`. Cost Propagation calls it per affected Draft Quote. No input schema has a total field, so client totals can't arrive.
- **Editor commands** (`src/line-items.ts`) return the standard `EditorResult` `{ quoteId, lines: LineItemView[], deletedLineIds, phases: PhaseView[], deletedPhaseIds, milestones: MilestoneView[], deletedMilestoneIds, totals }` (`lines` = inserted or changed rows as stored, `LineItemView` = the row minus `organizationId`/`createdAt` plus `plannerManaged` and `allocations: { periodStart, amount }[]`, so a command that changes Allocations returns them on the lines it touched; `allocationsByLine(scope, ids)` loads them). End a `quoteCommand` body with `return editorResult(cmd, { lineIds, deletedLineIds, phaseIds, deletedPhaseIds, milestoneIds, deletedMilestoneIds })`, which reprices and picks those rows; add fields to the shape rather than inventing another. Destructive commands save what they removed with `saveUndoSnapshot(scope, { quoteId, kind, payload, userId })` (table `undo_snapshots`, 10-minute TTL, server-side so a restore can't smuggle prices or costs) and return `{ undoToken, undoExpiresAt }`; the restore command reads it once with `takeUndoSnapshot(scope, { token, quoteId, kind })`. Lines go into a snapshot with `snapshotLines` and come back with `restoreSnapshotLines` (refused after the Quote's dates/Time Period changed or a source was deleted); `copyLines` clones lines with their Allocations; `quotePhases` / `quoteLineRows` / `quoteMilestones` load a Quote's tree and Milestones. `lineItemSourceUsage(scope, column, id)` gives the "in use" counts of a Catalog Item or Resource Role.
- **Line Item procedures** (all `quote.edit` commands through `quoteCommand`): `lineItem.add({ quoteId, phaseId?, items: [{ sourceKind, id }] })` (≤ 200 at once; active sources only; Base Rate = the source's current price/cost, unit price/cost start there; dates = Quote dates; quantity = `defaultLineItemQuantity` with the Organization's Hours Per Day; appended by `sequence`; no Allocations are created — the Planner (#15) lays them out), `lineItem.update({ quoteId, id, name?, description?, notes?, startDate?, endDate?, quantity?, unitPrice? })` (partial, field-level; dates within the Quote dates, end ≥ start → BAD_REQUEST; `unitPrice: null` resets to the Base Rate; on a planner-managed line quantity goes through `resizeAllocatedEffort`, a start change lifts and shifts its Allocations with `changeLineItemStart` (trimmed at the Quote End Date) and an end edit is PRECONDITION_FAILED), `lineItem.delete({ quoteId, ids })` (one gesture, returns `undoToken`) and `lineItem.restore({ quoteId, undoToken })` (same ids, Base Rates and Allocations; refused after the Quote's dates/Time Period changed or a source was deleted; a vanished Phase → no Phase). `lineItem.move({ quoteId, ids, phaseId, beforeId? })` (a drop or bulk move: the lines, in grid order, go into that Phase or none right before `beforeId` or at the end; the container is renumbered) and `lineItem.clone({ quoteId, ids, phaseId? })` (with Allocations; without `phaseId` each copy lands right after its original, with it they are appended there: "duplicate into"). Catalog Item / Resource Role deletion counts Line Items (`inUseError`, suggest deactivate) and the FKs RESTRICT. `catalogItem.listForPicker` / `resourceRole.listForPicker` are the Add Items sheet's cursor-paged lists (`cursor` = offset, `nextCursor` null at the end, for `useInfiniteQuery` via `trpc.….infiniteQueryOptions(input, { getNextPageParam: (p) => p.nextCursor })`).
- **Allocation procedures** (`routers/allocation.ts`): `allocation.setRange({ quoteId, cells: [{ lineItemId, periodStart, amount | null }] })` is one Planner gesture (≤ `ALLOCATION_BATCH_MAX` cells): per line `applyAllocationEdits` (caps, bucket normalisation, buckets overlapping the Quote dates); Resource Role lines only (BAD_REQUEST); one bad cell refuses the whole batch; quantity and dates follow Σ Allocations; returns `EditorResult` + `undoToken` for `allocation.restore({ quoteId, undoToken })`. Persist Allocations only through `writeAllocations` / `writeSchedule` from `src/allocations.ts` (diff-based upsert/delete plus the line's dates and quantity).
- **Phase procedures** (`routers/phase.ts`, all `quote.edit` through `quoteCommand`): `phase.create({ quoteId, parentId?, name })` (end of its siblings), `rename`, `move({ quoteId, id, parentId, beforeId? })` (with its subtree; `canPlacePhase` refusals → BAD_REQUEST, unknown parent → NOT_FOUND), `delete({ quoteId, id })` (cascades to descendant Phases, their Line Items and Allocations; returns `deletedPhaseIds`/`deletedLineIds` and `undoToken`), `restore({ quoteId, undoToken })` (same ids; back at the top level if the parent has gone) and `clone({ quoteId, id })` ("Copy of {name}" right after the original, with descendants, lines and Allocations). The grid computes delete counts client-side with `phaseRollups`; `apps/web/lib/phase-tree.ts` has the grid's visible rows, Phase picker options, the optimistic move helpers and `resolveDrop` (what a drag-and-drop means: onto a line = before it, a line onto a Phase row = into it, the end zone = top level). dnd-kit's `DndContext` needs a stable `id` (`useId()`) or SSR hydration mismatches.
- **Quote Documents** (`src/documents.ts`, `routers/quote-document.ts`): `quote_documents` (quote cascade, `version` unique per Quote, `storage_key` under `organizations/<id>/quote-documents/<id>.pdf`, `file_size`, `quote_snapshot`/`settings_snapshot` jsonb, `notes`, `captured_by_mark_sent`, `generated_by_id`, `generated_at`). `generateQuoteDocument(scope, quoteId, { actor, storage, notes?, capturedByMarkSent? })` locks the Quote row `FOR UPDATE`, assigns max(version) + 1, snapshots (`buildQuoteDocumentSnapshot`), renders on the server, stores the PDF and inserts the row, returning the view + both snapshots; it checks no permission (callers do) and runs in the caller's transaction, so Mark as Sent calls it inside its `quoteCommand` with `capturedByMarkSent: true`; it also returns the `storageKey` for cleanup by a caller whose transaction fails later (strip it before returning). Procedures (any member unless noted): `quoteDocument.previewSnapshot({ quoteId })` → `{ snapshot, settings, logo }`, `list({ quoteId })` (newest first, `canDelete` per row, `downloadUrl`), `generate({ quoteId, notes? })` (also on locked Quotes), `delete({ id })` (Owner or Admin; captured → PRECONDITION_FAILED; removes the object after the row). ## Tests

- Test external behaviour through public interfaces. Use no DB mocks, and don't assert on internal calls or query shapes.
- API tests are the primary seam. Put them next to the router (`src/routers/<area>.test.ts`) and call through the harness in `packages/api/src/test`, which runs against the real test database, rolls back every test, and makes nested transactions savepoints:
  ```ts
  it("…", () => withTestDb(async (db) => {
    const caller = createTestCaller(db)
    expect(await caller.health.check()).toMatchObject({ status: "ok" })
  }))
  ```
  Signed-in callers use `createTestCaller(db, { user: await createUser(db) })`, which injects the session. To exercise the real cookie lookup instead, use `createSession(db, user)` and pass its `cookie` in `headers`. Fixtures live in `src/test/fixtures.ts` and are re-exported from `../test`. Add shared fixtures there rather than writing setup in each test (e.g. `createAccount(db, organization, overrides?)`, `createContact(db, account, overrides?)`, `createCatalogItem(db, organization, overrides?)`, `createResourceRole(db, organization, overrides?)`, `createQuote(db, organization, { owner, account?, ...overrides })`).
- Organization-tier tests: `createOrganization(db, overrides?)`, `createMembership(db, { organization, user, role?, isApprover? })`, or `createMember(db, organization, { role?, isApprover?, user? })`, which returns `{ user, membership }`. Then call as that user on that Organization's subdomain with `organizationCaller(db, { organization, user })`.
- **Tenancy isolation gate (required).** Every organization-tier procedure that takes a record id gets an isolation test. `expectIsolated` creates an outsider Organization whose Admin is also an Approver, and calls the procedure both on the outsider's own subdomain and on the owner's subdomain. It expects NOT_FOUND or FORBIDDEN each time, and checks that `snapshot` reads the same before and after. Each attempt runs in a rolled-back savepoint.
  ```ts
  it("is isolated from other Organizations", () => withTestDb(async (db) => {
    const acme = await createOrganization(db)
    const account = await organizationScope(db, acme.id).insert(accounts, { name: "Initech" })
    await expectIsolated(db, {
      owner: acme,
      call: (caller) => caller.account.rename({ id: account.id, name: "Hacked" }),
      snapshot: () => db.select().from(accounts).where(eq(accounts.id, account.id)),
    })
  }))
  ```
  Procedures without a record id (like `organization.current`) instead test that a non-member is refused on the owner's subdomain.
- Object storage: every test caller gets a fresh `createMemoryStorage()`; pass your own `storage` to `createTestCaller`/`organizationCaller` to inspect `storage.objects`, and simulate a browser's presigned upload with `storage.put(key, bytes, { contentType })`.
- Email: every test caller gets an in-memory mailer. To read what was sent, pass `mailer: createMemoryMailer()` to `createTestCaller`/`organizationCaller` and inspect `mailer.outbox`; `tokenFromEmail(message)` extracts the Invitation token from the accept link. `createInvitation(db, { organization, email?, role?, expiresAt?, acceptedAt?, revokedAt? })` inserts one directly and returns `{ invitation, token }`.
- Domain tests are table-driven Vitest in `packages/domain/src/**/*.test.ts`.
